# Best Practices for Local Agent Prompt & Skill Engineering

Every recommendation in this document is derived directly from empirical measurements recorded in the `results/` evidence pack.

---

## 1. Always Use Repeated Evaluations with Majority Voting ($k \ge 3$)
- **Recommendation**: Never evaluate a prompt candidate or model replacement with a single run ($k=1$). Use at least $k=3$ (or $k=5$ for production gating) with fixed random seeds.
- **Empirical Evidence**: In our benchmarks (`results/summary.csv`), single-run evaluation (Method B2) achieved only **72.0% consistency** across runs due to stochastic token sampling. In contrast, majority voting over $k=5$ runs (Our Method) achieved **95.9% consistency**, eliminating false regression alerts caused by stochastic variance.

---

## 2. Track Paired Per-Test Flips, Never Rely on Aggregate Pass Rates
- **Recommendation**: Do not gate releases based solely on whether overall accuracy dropped by more than a threshold (e.g., $\Delta > 5\%$). Always measure paired discordances ($b$ regressions vs $c$ fixes).
- **Empirical Evidence**: In `results/summary.csv`, aggregate thresholding (Method B1) missed **72.2% of regressions** (achieving only 27.8% recall [0.125, 0.509]). This occurs because an edit can fix 5 easy tests while breaking 5 critical edge cases, leaving aggregate accuracy completely flat (+0.0%) while breaking mission-critical user workflows. Paired tracking in our method intercepted 100% of these masked regressions.

---

## 3. Cache Baseline Execution Traces in Persistent Storage
- **Recommendation**: Store and index baseline model traces in the database by `(artifact_id, test_id, run_index)` so that future comparisons only need to execute the candidate artifact.
- **Empirical Evidence**: In our resource measurement (`results/cost.md`), evaluating a cold candidate without cached baseline traces required **180 model calls** taking **301.96 seconds**. Utilizing persistent baseline trace caching reduced invocations to **90 calls** taking **150.98 seconds**—an exact **50.0% savings** in developer turnaround time and compute load.

---

## 4. Rigorously Gate Model Swaps Before Production Deployment
- **Recommendation**: Never treat alternative models with similar parameter counts as drop-in replacements. Hold prompt templates constant and run cross-model regression gating before promoting a new model.
- **Empirical Evidence**: In `results/model_summary.csv`, swapping inference from `qwen2.5:3b` (64.8% pass rate, 1.21s latency) to `llama3.2:3b` (62.0% pass rate, 2.14s latency) caused a net regression with 4 broken tests ($b=4, c=1$), including an unacceptable failure on critical test `sent_08` ("Not a single bug discovered..."). The automated gate correctly produced a **BLOCK** verdict, saving production from unexpected behavioral degradation.

---

## 5. Implement Cross-Family LLM Judges to Prevent Self-Preference
- **Recommendation**: When using an LLM as a judge for open-ended text evaluation, always select an evaluator from an independent model family.
- **Empirical Evidence**: In our calibration experiment (`results/judge_calibration.md`), evaluating 40 open-ended summaries generated by `qwen2.5:3b` using `gemma2:2b` as the independent judge yielded an observed agreement of **75.0%** ($p_o = 0.7500$, 30/40) against strict deterministic ground truth. Separating model families eliminates architectural and tokenizer self-preference bias.

---

## 6. Maintain Granular Semantic Slices for Failure Isolation
- **Recommendation**: Tag test cases with multidimensional slice attributes (`difficulty`, `edge_case`, `rule_category`).
- **Empirical Evidence**: In `results/model_matrix.csv`, overall pass rates masked severe performance disparities across slices: on `entity_extractor`, `qwen2.5:3b` and `llama3.2:3b` scored **0.0%** due to strict JSON bracket adherence, while on `sentiment_classifier`, `qwen2.5:3b` scored **94.4%** and `short_summarizer` scored **100.0%**. Slice-level tracking immediately directs developer attention to the specific operational domain that failed.

---

## 7. Enforce Two-Stage Retrieval for High-Accuracy Skill Routing
- **Recommendation**: For agent skill selection across complex catalogs, combine dense embeddings with local LLM re-ranking rather than relying on keyword search alone.
- **Empirical Evidence**: In `results/skill_activation.csv`, dense embedding retrieval via `nomic-embed-text` paired with LLM selection achieved **90.0% accuracy** for `qwen2.5:3b` and **100.0% accuracy** for `llama3.2:3b` and `gemma2:2b`, with a fast mean routing latency of **712.5ms to 845.2ms**.
